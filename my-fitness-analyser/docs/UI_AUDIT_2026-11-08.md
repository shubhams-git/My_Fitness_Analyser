# Interface audit and implemented refinement

8 November 2026. Scope: sign-in, training, progress, activity/map/analysis,
body/strength journal and account. Technical audit plus rendered manual review;
not an independent WCAG certification or a claim of physical Safari testing.
The existing athletic Field Notes identity remains the design system.

## Findings and disposition

| Severity | Finding / impact | Resolution |
|---|---|---|
| P1 | Mobile saved check-ins said “Browser-only preview” even for persisted member records, undermining confidence in the save | Both initial render and refreshed dock now use actual storage scope |
| P2 | Navigation varied by screen and mobile detail CSS hid new/global destinations | Common Training / Progress / Journal / Account destinations; Activities remains a local chooser; all are visible on phone |
| P2 | Large introductory type, numbered labels and repeated page entrances delayed access to training instruments | Compact athletic headings, functional shortcuts, removed decorative numbering and short nonblocking overview entrance |
| P2 | Extreme pace tails flattened the useful range of a real GPS run | Disclosed focused range with omitted count; full range remains available; original values still inspectable |
| P2 | Latest HR sparkline lacked a visible scale | Lower/upper bpm labels added; full detail remains linked |
| P2 | Account/sign-in brand, badges and footer copy dropped below 11–12 px | Raised visible functional text to a 12 px floor and retained 16 px form inputs |
| P2 | Oversized AI heading and implementation-heavy framing dominated the overview | Compact coaching heading/findings with original evidence and consent actions retained; Progress precedes the briefing |
| P3 | Header brand mark differed between Training and Journal | Existing slash mark used consistently |

No P0 blocker was observed in the inspected paths. Authentication/data isolation
continue to be covered by existing HTTP/PostgreSQL tests; this UI pass does not
alter their authorization model.

## Impeccable source detector

One completed scan returned 29 warnings/advisories, including undersized text,
gradient text, glows, decorative grids/stripes and a heading-label pattern.
Source scanning follows linked CSS, including historical/overridden selectors;
counts are not counts of visible defects or a pass/fail accessibility verdict.
The visible small account/sign-in text was verified and fixed. Several gradient,
grid and glow warnings originate in legacy styles or selectors overridden by
the selected theme/refinement layer. Weekly chart grid lines and chart area
fills express measurements, rather than decorative page backgrounds. The
active athletic lighting and real map framing remain intentional design choices.
The raw result is ignored in `private-data/interface-qa/impeccable-detection.json`.
No overlay was injected and no claim of a live Impeccable browser overlay is made.

## Checks and retained strengths

82 tests pass. Best-effort interpolation includes end-aligned candidates,
stationary elapsed time and explicit gaps. Distributions weight time rather
than sample count. Monthly totals preserve multiple same-day activities and
leap-month dates. Source records are never rewritten by charting.

The map remains real, navigable street geography with attribution. Weight
trend geometry, real reading dots, interpolation labels and held tail remain
intact. Quick logging, four unanswered check-in questions, explicit Gemini
permission and evidence citations remain available. Hosted empty accounts do
not turn into demos. No new paid API or SQL migration is needed.

The skill context reported a legacy PRODUCT.md schema. The existing product
contract was retained; migrating skill metadata is optional and outside this
interface feature.
